## アクセス制御

- 公開データと別テーブル。anon/publicへの権限は与えない。
- 匿名認証で発行されたユーザーIDと auth.uid() が一致する行だけに SELECT/INSERT/UPDATE/DELETE を許可する。
- ユーザーIDが主キー。履歴は蓄積せず最新1件だけを上書きする。
- 数値の範囲をDBでも検証する。座標をURL・ログ・公開APIに含めない。
- 取得は明示操作の1回だけ。watchPosition・自動追跡・カメラ映像の送信は使わない。
- サービスロールキーをフロントエンドに渡さない。
- 匿名セッションはブラウザーに保存される。データ消去後に同じ利用者として復元できるとは限らない。削除ボタンで位置情報を消してからブラウザーデータを消すこと。
- 管理者権限やサービスロールはRLSを迂回できるため、「本人限定」は通常の利用者間の分離を意味する。

## 公開前の運用設定

匿名認証を一般公開する前に、Supabaseの認証レート制限とCAPTCHAを設定する。CAPTCHAを有効にした場合、この画面にも対応するチャレンジと captchaToken の受け渡しを追加してから公開する。現在の実装は既存設定を迂回せず、チャレンジが必要な場合は保存に失敗する。

位置情報の保存は利用目的を明示して利用者が押したときだけ行う。放置された匿名ユーザーの位置情報の保持期間は、公開前に運用側で決めて削除する。現在は自動削除ジョブを作成していない。


RLSテストはPGlite内にテスト専用ユーザーと認証関数を作り、実際のSQLを実行する。本番DBへアクセスせず、未認証・本人・別ユーザー・不正な所有者変更を検証する。Supabaseの本番設定や端末の権限を検証したことにはならない。

## WebとWebXR

Webはカメラ・環境モデルなしで泡を表示する。実環境の表示はWebXR immersive-arでのみ行う。カメラ映像の直接取得・送信は行わない。現在地取得は場所ページでの明示操作時だけで、自分の思い出ページは現在地を取得しない。詳細は [ページ仕様](web-and-xr-views.md) を参照。WebXRの実機動作は別途確認する。
