# Cloud Dome — Web用・空間モデル

## ファイル

- `cloud-dome.glb` — 推奨。白いドーム、なだらかな浅い底面、半透明の水面。グリッドなし。
- `cloud-dome-grid.glb` — 床とドームの確認用グリッドを含む版。
- `cloud-dome-three.js` — Three.js用の任意の補助コード。昼光・動的な映り込み・水面アニメーションの再生を設定。
- `manifest.json` — 正確なファイルサイズと三角形数。

GLBには形状、PBRマテリアル、埋め込みPNGテクスチャ、
標準glTFモーフアニメーション `Gentle_Water_Loop` が含まれます。
外部画像・CDN・Draco/Meshoptデコーダーは不要です。
グリッドなし版は2メッシュです。水面の6つのモーフターゲットで元の3つの波を表現します。

UI、カメラ、コントローラー、テレポート、移動処理、壁侵入時の暗転、
他の物体は含まれていません。GLB自体にライトは含めず、読み込み先で照明を設定します。

## スケールと配置

- 単位：メートル、Y-up。全体をスケール1で配置。
- 中心：`[0, 0, 0]`。平均水面の高さ：Y = 0。
- ドーム：直径約6.2m、上端Y = 3.1m。
- 水場：直径約5.3m、中央の底面Y = -0.06m（水深約6cm）。
- 波高：最大約±5.4mm。外周では波と透明度がなだらかにゼロへ。
- PCカメラの目安：`[0, 1.6, 0]`。VRは中心からlocal-floorで開始。
- 歩行可能半径の目安：2.35m。コリジョンは含まれないため、利用先で設定してください。
- 内側からも見えるようにドームは両面マテリアルです。

## Three.jsで使用

Three.js 0.186系で書き出しています。npm等で`three`を利用できるプロジェクトに、
GLBと補助ファイルをまとめてコピーしてください。

```js
import { loadCloudDome } from "./cloud-dome-three.js"

const space = await loadCloudDome({
  scene, // 利用先のTHREE.Scene
  renderer, // 利用先のTHREE.WebGLRenderer
  url: "/models/cloud-dome.glb",
})

// 利用先の既存のレンダーループ内（VRならsetAnimationLoop）
space.update(deltaSeconds)
renderer.render(scene, camera)

// シーンを破棄する際
// space.dispose()
```

レンダラーはsRGB出力・ACESFilmicToneMapping・露出1を推奨します。
補助コードは環境光1.1、半球光1.15、左上の主光2.8、補助光0.45を追加します。
すでに照明がある場合は`daylight: false`を指定し、二重に加算しないでください。

補助コードの反射は128pxのキューブマップを低頻度で更新します。
VRでは約1.5秒ごと、通常表示では約0.75秒ごとです。
平面鏡のように厳密な反射ではなく、元の空間と同じ近似的な柔らかい映り込みです。
独自の環境マップを使う場合は`reflections: false`にしてください。
補助コードはWebXRセッションやカメラ、移動操作を作成しません。

## 他のエンジン・ビューアで使用

GLBを通常のglTF 2.0モデルとして読み込み、`Gentle_Water_Loop`をループ再生してください。
再生しない場合でも、初期状態の波形が表示されます。
ループは約125.66秒で、元の3つの波の速度が途切れずにつながります。

明るい照明と環境マップを設定してください。glTFには環境光・半球光・
リアルタイム反射プローブの標準的な移植方法がないため、これらはGLBだけでは再現されません。
必要に応じてクリアコート、IOR、テクスチャ変換のglTF拡張に対応したローダーを使用してください。
水面は透明ブレンド方式で、重いスクリーンスペース屈折は使用していません。
水面を不透明物より後に描画し、透明面の深度書き込みはOFFにしてください。

Quest実機・他エンジンでの見え方や72/90fpsは未検証です。
